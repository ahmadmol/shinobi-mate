# سحابة الذكر — Spiritual Cloud

ميزة اختيارية مستقلة لكل نسخة Mascot، جاهزة في المصدر والنسخة المحمولة.
النصوص الدينية مأخوذة حرفيًا من `shinobimate_spiritual_messages_100.md` المرفق.
لم تُنشأ نصوص جديدة، ولم تتغير العبارات أو التشكيل أو علامات الترقيم، ولم تُضف نسب إلى مصادر.
أزيل من العرض فقط رقم القائمة ووسم القسم وتنسيق Markdown؛ نسخة المصدر محفوظة بجانب هذا التقرير.

## ملفات المصدر الجديدة

داخل `src/main/java/com/group_finity/mascot/cloud/`:

| الملف | الوظيفة |
| --- | --- |
| `CloudMessages.java` | قراءة UTF-8 من حزمة الشخصية الحالية وترتيب مفاتيح message.N رقميًا |
| `CloudState.java` | HIDDEN / HOVER_VISIBLE / PINNED، العبارة الحالية، العشوائية والتوقيت المستقل |
| `ClickGesture.java` | فصل النقرة عن السحب بإحداثيات المؤشر على الشاشة |
| `CloudPlacement.java` | اختيار الشاشة الفعلية وضبط الموضع وحدود العرض |
| `CloudPanel.java` | رسم حدود السحابة وتشكيل العربية والالتفاف والمركزة |
| `SpiritualCloud.java` | نافذة Swing قابلة لإعادة الاستخدام، التحديث على EDT، إدارة الإظهار والإخفاء والتنظيف |

ملفات جديدة أخرى:

- `tools/import-spiritual-messages.ps1`: استخراج وتوزيع النصوص بصورة قابلة لإعادة التنفيذ، مع حفظ مجموعات الحزم الغائبة دون إنشائها.
- `tools/SpiritualCloudCheck.java`: فحص البيانات والحالات والإيماءات والمواضع وكل تخطيطات النصوص.
- `tools/SpiritualCloudDesktopCheck.java`: تشغيل Main والنوافذ الأصلية على Windows واختبار السحابة من مستمعات الإدخال الحقيقية.
- `art/spiritual-cloud/shinobimate_spiritual_messages_100.md`: نسخة المصدر.
- `art/spiritual-cloud/distribution.json`: أرقام النصوص الأصلية لكل شخصية.
- `img/<CharacterName>/conf/cloud_messages_ar.properties`: خمسة ملفات مستقلة؛ تُنسخ أيضًا إلى مجلدات الحزم الموجودة تحت `Shimeji-ee/img/`.
- هذا التقرير ومعاينة `output/spiritual-cloud-gallery.png` وسجلات الاختبارات تحت `output/`.

## الملفات المعدلة

- `Mascot.java`: سحابة وإيماءة مستقلتان لكل instance، enter/exit، تأجيل press العادي حتى تجاوز مسافة السحب، تحديث موضع السحابة من apply، إعادة تحميلها عند التحول وتنظيفها عند التخلص من الشخصية.
- `Main.java`: إعادة تحميل بيانات السحابة للنسخ الحالية عند إعادة تحميل إعدادات الحزمة.
- `behavior/UserBehavior.java`: تسجيل بداية السحب فور إنشاء سلوك Dragged لتلقي release السريع قبل أول tick بطريقة صحيحة.
- `README.md`: توثيق الميزة.
- `Shimeji-ee/app/Shimeji-ee.jar`: استبدال الملف كاملًا بنتيجة Maven. النسخة الأصلية محفوظة في `output/spiritual-cloud-backup/Shimeji-ee.jar`.

## Architecture

كل Mascot يمتلك SpiritualCloud الخاص به. لكل سحابة CloudState مستقل وقائمة ورسالة وتوقيت وحالة تثبيت مستقلان، حتى لنسختين من الشخصية نفسها.

يعيد المحرك استخدام دورة Manager الحالية كل 40 ms. لا توجد Timer أو thread إضافية للسحب؛ يعتمد التوقيت على System.nanoTime.
تُجمع تحديثات EDT المتأخرة، ولا ترسل السحب المخفية تحديثات دورية. يوجد cache مشترك لحدود الشاشات يُحدَّث مرة كل ثانية.
تُنشأ JWindow عند أول إظهار وتُستخدم مجددًا؛ التخطيط والرسم النصي يُعادان عند تغير النص أو مساحة الشاشة فقط.
النافذة غير قابلة للتركيز، وتمر أحداث الماوس خلالها على Windows. يتم التخلص منها مع Mascot، مع منع إعادة الإنشاء بعد dispose.

## التفعيل الديناميكي وإعادة التحميل

يقرأ المحرك المسار:

```text
<app.dir أو user.dir>/img/<الحزمة الحالية>/conf/cloud_messages_ar.properties
```

مثال بنيوي، دون عبارات بديلة:

```properties
message.1=<نص من المصدر المعتمد>
message.2=<نص آخر من المصدر المعتمد>
```

الملف UTF-8، ولا توجد أسماء شخصيات أو قائمة حزم ثابتة داخل محرك السحابة.
غياب الملف، أو عدم وجود عبارتين مختلفتين صالحتين، يعطل السحابة للحزمة فقط؛ لا تظهر نصوص عامة احتياطية.
أي حزمة جديدة تدعم الميزة بإضافة هذا الملف. إعادة التحميل أو تغيير الحزمة تعيد الحالة إلى HIDDEN وتحمل البيانات الجديدة.

## التفاعل والتوقيت والرسم

- Hover يعرض HOVER_VISIBLE. الخروج يخفيها إذا لم تكن PINNED.
- النقرة الأولى تثبتها. الثانية تخفيها حتى يخرج المؤشر ويعود فعلًا، فلا يعيد hover إظهارها فورًا.
- حد السحب `ClickGesture.DRAG_THRESHOLD = 6` بكسلات. تُقاس أقصى مسافة من موضع الضغط على الشاشة، وتظل الإيماءة سحبًا حتى لو عاد المؤشر إلى موضع البداية.
- أحداث السحب تتبع المحرك الحالي بعد تجاوز الحد. Hotspots الفعالة تحتفظ بسلوك الضغط، وRight Click يتابع مساره الأصلي.
- مدة التغيير `CloudState.MESSAGE_INTERVAL_MILLIS = 6000`. مدة fade لكل اتجاه `FADE_MILLIS = 180`؛ يبدأ الانتقال عند الموعد وتتبدل العبارة عند انتهاء fade out.
- الاختيار يستبعد العبارة الحالية مباشرة، دون حلقات إعادة اختيار عشوائية.
- العرض من 160 إلى 340 بكسل، ويُقلَّص إلى مساحة الشاشة عند الحاجة. يلتف النص تلقائيًا؛ النصوص المرفقة كلها اجتازت حد ثلاثة أسطر.
- الخط مشتق من خط الواجهة الحالي مع بديل Dialog داعم للعربية، بحجم 16 ويقل إلى 13 عند الحاجة إلى ثلاثة أسطر.
- Java2D TextLayout وLineBreakMeasurer يوفران RTL والتشكيل، ويُوسَّط الحبر الفعلي للنص.
- أبيض شبه شفاف، حدود سماوية 1.6 بكسل وظل خفيف، بحواف Bézier على شكل سحابة.

## الحركة والشاشات

يرتبط الموضع بالمكوّن الفعلي للشخصية بعد تطبيق صورة الحركة، بما يشمل تغير ImageAnchor.
يظهر فوقه متمركزًا بهامش 8 بكسلات، وينتقل إلى الأسفل أو الجانب عند ضيق المساحة أعلى الشاشة.
تُختار شاشة واحدة حسب مساحة التقاطع ثم أقرب شاشة؛ لا تستخدم السحابة المستطيل الجامع الذي قد يشمل فراغات بين الشاشات.
تُضبط الإحداثيات داخل مساحة عمل الشاشة، بما يشمل الإحداثيات السالبة وشريط المهام.

## توزيع النصوص

التوزيع بالتناوب يحافظ على مزيج من الأقسام الأربعة لكل شخصية. عشرون نصًا لكل حزمة، والمجموع 100 بلا تداخل.

| الشخصية | أرقام النصوص الأصلية |
| --- | --- |
| NarutoShippuden | 1، 6، 11، …، 96 |
| SasukeShippuden | 2، 7، 12، …، 97 |
| GojoSatoru | 3، 8، 13، …، 98 |
| SukunaRyomen | 4، 9، 14، …، 99 |
| AstaBlackClover | 5، 10، 15، …، 100 |

AstaBlackClover موجودة فعلًا، ولذلك تم تثبيت مجموعتها، ولم تُنشأ أي حزمة وهمية.
ملف distribution.json يحتوي القائمة الكاملة للأرقام. فُحصت مطابقة كل قيمة محملة مع المصدر حرفيًا.

## البناء والاختبار

البناء النهائي باستخدام Maven المرفق وJDK 25، مع target/release 21:

```powershell
$env:JAVA_HOME='C:/Program Files/Android/Android Studio/jbr'
./tools/maven/apache-maven-3.9.9/bin/mvn.cmd clean package
```

النتيجة BUILD SUCCESS؛ الملف الناتج target/ShinobiMate.jar، ثم نُسخ كاملًا إلى تطبيق Windows المحمول.
توجد تحذيرات Maven Shade الخاصة بالـ manifests/licenses وmodule-info، ولا توجد أخطاء بناء.
لم يُستخدم jar uf ولا git add ولا git commit ولا git push.

الاختبارات المستقلة تُجمَّع بـ javac --release 21 وتعمل على الملف المبني:

```powershell
& "$env:JAVA_HOME/bin/javac.exe" --release 21 -encoding UTF-8 -cp target/ShinobiMate.jar -d output/spiritual-cloud-tests tools/SpiritualCloudCheck.java tools/SpiritualCloudDesktopCheck.java
& "$env:JAVA_HOME/bin/java.exe" -cp 'output/spiritual-cloud-tests;target/ShinobiMate.jar' SpiritualCloudCheck
```

- `spiritual-cloud-check.log`: نجح 11,593 تحققًا؛ النصوص حرفية، خمس مجموعات منفصلة، حالات مستقلة، منع التكرار، إيماءات، 10,000 حالة شاشة، وتخطيط ورسم جميع النصوص العربية.
- `spiritual-cloud-regression.log`: نجح 197,582 تحققًا من الاختبارات القائمة عبر 196,839 tick للمحرك؛ الحركات هنا تستخدم نوافذ اختبار في الذاكرة، والـ Character Chooser هو Swing الفعلي.
- `spiritual-cloud-desktop-check.log`: نتائج اختبار Main والنوافذ الأصلية على Windows، لكل الشخصيات الخمس ونسخة إضافية من نفس الشخصية، وعلى الشاشتين المتصلتين.
- فُحصت معاينة كل أقسام النصوص بصريًا، وفُحصت لقطات سحب Swing الفعلية باستخدام computer-use.

اختبار سطح المكتب يرسل MouseEvents إلى مكونات الشخصيات ومستمعاتها في المصدر؛ ليس مجرد اختبار CloudState منفصلًا.
يشمل Hover، الخروج، التثبيت والإلغاء، السحب وعدم تغيير التثبيت، قائمة Right Click العربية، تغير النص بعد ست ثوانٍ، استقلال النسخ، إعادة استخدام النافذة، الحركة، Follow Cursor، إعادة التحميل، وحدود الشاشات، والتخلص من النوافذ.
اختبارات الحركة تستخدم Actions الأصلية وتتحقق من موضع السحابة بعد كل تحديث.

## الحدود المتبقية

لا توجد مشكلة وظيفية باقية ظهرت في الاختبارات. الفحص الآلي للإدخال يتم عبر أحداث AWT داخل التطبيق، ولذلك يبقى تقييم إحساس السحب الطبيعي وشكل التصميم النهائي للمستخدم أثناء تجربته اليدوية.
الفحص البصري تحقق من الخط والتشكيل والالتفاف في البيئة الحالية؛ يعتمد بديل الخط على الخطوط المتاحة عند تشغيله على جهاز آخر.
