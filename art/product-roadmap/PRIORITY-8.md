# Priority 8 — Sound, portable, installer preparation and updates

Sound categories UI/CHARACTER/COMBAT/VFX use four reusable original synthesized PCM cues. Settings saves, character clicks, combat impact and charge events are wired to these categories. Master/category gains and mute are live; unavailable devices retry after a bounded delay and failed clips close. Native audio checks successfully opened all four clips on this host, verified gains/mute and released the native resources.

Portable packaging uses the bundled OpenJDK 21 `jpackage` ToolProvider to build a genuine branded app-image. A source Maven JAR is staged with the Java 21 runtime, validated pack data, localization, icon and license. The ZIP excludes source, target, output, logs, IDE/test files and helper scripts. Previous generated distributions are backed up under output rather than silently overwritten. No existing JAR is patched.

Real launcher smoke testing starts `ShinobiMate.exe` from a different working directory on its bundled Java 21, with five packs, Arabic context menu, manual battle pairs, cloud pin/hide, click-through, stop/rematch/disposal. It passed 744 assertions. Separate real-runtime measurements cover one/five pets under LOW/BALANCED/HIGH. These are short idle-desktop measurements, not a combat stress or long-term leak benchmark.

The documented Inno Setup 6 per-user recipe includes install, Start Menu, optional unchecked desktop/startup tasks and uninstaller. Existing user settings/progress/custom messages are preserved. **Installer status: PARTIAL**. ISCC.exe is absent, so Setup.exe compilation, install and uninstall have not been tested. No external compiler was downloaded. See [installer toolchain documentation](../../tools/installer/README.md).

Update checking is explicit, HTTPS-only, bounded to 64 KiB, with connection/request/body deadlines and no redirects. It accepts version/downloadPage metadata or GitHub tag_name/html_url release metadata; draft/prerelease results do not offer an update. The UI opens the HTTPS release page only after the user clicks it. There is no executable download, silent execution or automatic updater. The publisher's official HTTPS endpoint must be configured in Settings/About; none is invented. A real local TLS server fixture tested new/same version, GitHub format, malformed versions, unsafe URLs, redirect and oversized response rejection. Both update-dialog languages were rendered.

Windows startup handling now prefers the product launcher, supports old shortcut recognition and uses a hidden encoded PowerShell helper with escaped paths and a ten-second deadline. Automated checks did not enable the user's actual startup setting. Installer lifecycle and interactive startup enable/disable remain manual release checks.

Native startup-helper verification also created/read an actual .lnk in an isolated temporary folder and checked its target/working directory with spaces/apostrophes. UTF-8 batch fallback with Unicode/percent paths was checked separately. The user's Startup directory was not modified.
