# تقرير Character Combat MVP — ShinobiMate

## التشغيل

افتح نسختين أو أكثر من الشخصيات المدعومة، ثم استخدم:

**زر أيمن على الشخصية → ⚔ القتال → اختيار خصم → اسم الشخصية #رقم النسخة**.

القائمة تعرض النسخ الموجودة فعليًا على سطح المكتب، باستثناء الشخصية صاحبة القائمة. الأرقام هي معرفات ثابتة لكل Mascot instance. الخصوم المشغولون بمباراة، والحزم غير الداعمة للقتال، يظهرون كخيارات معطلة. أثناء المباراة يتاح «إيقاف القتال» على الطرفين، ويُقفل اختيار الخصم. بعد الإيقاف أو نهاية المباراة يصبح «إعادة المباراة» متاحًا إذا كانت النسخة السابقة لا تزال موجودة ومتاحة.

لا يبدأ القتال من الاقتراب، التشغيل، السلوك العشوائي، أو مرور الوقت. لا يوجد Auto Battle. المباراة تربط نسختين محددتين، ولا تبحث عن هدف آخر ولا تسمح للشخصيات الأخرى بإلحاق الضرر بالمقاتلين. يمكن تشغيل أزواج منفصلة يدويًا؛ لا توجد مباريات فرق.

## البنية والملفات

الملفات الجديدة في `src/main/java/com/group_finity/mascot/combat/`:

| الملف | الوظيفة |
|---|---|
| `CombatProfile.java` | قراءة إعدادات XML للحزمة، التحقق من القيم والمراجع والأصول، منع DTD والكيانات الخارجية |
| `CombatState.java` | الحالات المستقلة عن Behavior System |
| `CombatMatch.java` | نموذج مباراة 1v1، القرارات، الطاقة، الاصطدام، المقذوفات، الضرر، والدورة الكاملة للمباراة |
| `CombatEngine.java` | إدارة الأزواج، قائمة الخصوم، الإيقاف، إعادة المباراة، ربط النموذج بـMascot والرسومات |
| `CombatEffects.java` | نافذة شفافة واحدة قابلة لإعادة الاستخدام لكل زوج؛ رسم مؤثرات PNG مستقلة لا تلتقط الماوس |

ملفات جديدة أخرى:

- `img/<Character>/conf/combat.xml` لكل واحدة من الشخصيات الخمس، ونسخة مطابقة تحت `Shimeji-ee/img/`.
- `img/<Character>/combat/vfx/*.png`: أربع إطارات لكل مؤثر، 40 ملف PNG شفاف لكل حزمة، بإجمالي 200 أصل فريد ونسخها في البرنامج المحمول.
- `tools/BuildCombatPacks.java`: مولّد الإعدادات والمؤثرات الأصلي والقابل لإعادة التشغيل.
- `tools/CombatCheck.java`: اختبارات النموذج وربطه الفعلي بالمحرك والقائمة والسحب.
- `tools/CombatDesktopCheck.java`: اختبار تشغيل Main ونوافذ Windows والمؤثرات والسحابة.
- `tools/check-combat.ps1`: بناء واختبار مع سجلات محفوظة في `output/`؛ خيار `-Desktop` يضيف الاختبار المرئي.
- هذا التقرير.

الملفات المعدلة لهذه الميزة:

- `Manager.java`: امتلاك CombatEngine واستدعاؤه مرة واحدة في تحديث المحرك الحالي، وتنظيف العلاقات عند إزالة الشخصية.
- `Mascot.java`: قائمة القتال، تعليق السلوك العادي للمقاتلين فقط، إحصاءات القتال في Debug، الإيقاف عند السحب أو تغيير السلوك أو الحزمة، والتنظيف عند الإغلاق. ترتيب قفل أحداث الماوس يتوافق مع قفل المحرك.
- `Main.java`: إنهاء المباراة عند إعادة تحميل إعدادات أحد المقاتلين.
- `image/ImagePairLoader.java`: احترام `app.dir` عند قراءة الصور الخارجية.
- `win/WindowsNativeImage.java` و`win/WindowsTranslucentWindow.java`: تحجيم bitmap ليتطابق مع الحجم الفعلي لنافذة Windows عند DPI مختلف؛ تخزين أحجام العرض مؤقتًا حتى أربعة أحجام للصورة؛ Cleaner لتحرير مقابض GDI عند زوال الصور.
- ملفات `language.properties` و`language_ar.properties` و`language_en.properties` و`language_zh.properties` تحت `conf/` و`Shimeji-ee/conf/`.
- `README.md` وإصدار JAR المحمول تحت `Shimeji-ee/app/Shimeji-ee.jar`.

التعديلات السابقة على الصور والسحابة والحزم بقيت موجودة. لم يُنفّذ Git commit أو push.

## صيغة Combat Profile

اختير XML لأنه يلائم إعدادات المشروع الحالية، دون إضافة مكتبة JSON. الملف اختياري، ومساره `img/<CharacterName>/conf/combat.xml`. يقرأه المحرك عند كل بدء مباراة أو إعادة مباراة؛ لا توجد أسماء شخصيات داخل محرك القتال.

الوحدات: المسافات بالبكسل عند Scaling=1، والأوقات بعدد تحديثات المحرك؛ التحديث الواحد **40ms**. جميع الإحداثيات المحلية بالنسبة لمرساة القدم. الـhitbox مؤلف باتجاه اليمين، ويعكسه المحرك عند الهجوم نحو اليسار؛ صور الحزم ومؤثراتها مؤلفة نحو اليسار، ويعكسها عارض الصور عند الاتجاه لليمين.

مثال لهجمة من ملف ناروتو:

```xml
<attack id="rasengan" kind="special" minRange="65" range="235"
        damage="26" cooldown="120" startup="13" active="14" recovery="17"
        speed="12" projectileSpeed="0" knockback="65" jumpHeight="0"
        cost="35" weight="1.3" animation="dash" chargeAnimation="charge"
        effect="energy" clone="false">
  <hitbox x="14" y="-102" width="86" height="100"/>
</attack>
```

الأقسام:

- `combat`: الإصدار، أبعاد صورة الشخصية، مرساة القدم، وسرعة الاقتراب.
- `hurtbox`: الجسم القابل للإصابة؛ الحزم الحالية تستخدم صندوقًا بعرض 46 وارتفاع 87، أصغر من صورة 128×128.
- `personality`: aggression، technique، dodge، block، counter، taunt، سرعة التفادي وارتفاع قفزته، cooldown وكلفة الطاقة للدفاع، تقليل ضرر الصد، احتمال صد المقذوف بالكامل، ونوع مؤثر الدفاع.
- `animations`: معرفات حركات تحتوي على `frame image="..." ticks="..."`. يتم تحميل الصور مرة وإعادة استخدام native bitmaps مع مرساة مستقرة خاصة بالقتال، لأن السلوك العادي قد يستخدم الصورة نفسها بمرساة الحائط أو السقوط.
- `effects`: إطارات PNG، مدة الإطار، وصورة clone اختيارية. النسخة المؤقتة مجرد رسم شفاف ولا تنشئ Mascot أو تدخل Character Manager.
- `attacks`: معرف ونوع الهجمة، مجال المسافة، hitbox، damage، cooldown، startup، active، recovery، سرعة الاندفاع والمقذوف، knockback، القفز، كلفة الطاقة، وزن القرار، حركات الشحن والهجوم، والمؤثر. `kind` يقبل melee/ranged/dash/special/aerial. `projectileSpeed > 0` يجعل الهجمة مقذوفًا. `knockback < 0` يجذب الخصم بدل دفعه.

لإضافة حزمة جديدة: انسخ بنية أحد الملفات، عرّف الصور والمؤثرات الموجودة في تلك الحزمة، واضبط الشخصية القتالية والهجمات. الملفات الناقصة أو القيم غير الصالحة تمنع بدء المباراة وتُسجل في السجل؛ يستمر عمل الشخصية العادي.

## الحالات ودورة المباراة

الحالات الموجودة:

```text
IDLE → SEEK_TARGET → APPROACH → ATTACK / SPECIAL_ATTACK
                            ↘ DODGE / BLOCK
ATTACK → RECOVER → APPROACH / ATTACK
إصابة → HIT → KNOCKBACK → RECOVER
HP=0 → HIT → KNOCKBACK → KO
الطرف الآخر → VICTORY
ثم العودة إلى NON_COMBAT
```

- تنتظر البداية 25 تحديثًا تقريبًا، أي ثانية، مع توجيه المقاتلين وإنزالهما تدريجيًا إلى أرض سطح المكتب إذا لزم. لا يُنقلان إلى منتصف الشاشة.
- تستخدم المباراة شاشة المقاتل الأول وحدود العمل الخاصة بها. إذا كان الخصم خارج تلك الشاشة، يُضبط إلى حدود الساحة كي تبقى المباراة قابلة للوصول؛ هذه هي حالة النقل الضروري. تتجنب الساحة مزج إحداثيات Win32 الفيزيائية مع إحداثيات Swing المنطقية.
- يبدأ الطرفان بـ100 HP و100 طاقة. تتجدد الطاقة تدريجيًا، وتتطلب بعض الهجمات والدفاعات كلفة طاقة.
- الاختيار يعتمد على المسافة والـcooldown والطاقة والأوزان والشخصية القتالية، مع randomness محدود. انخفاض الصحة يزيد الميل للدفاع.
- كل ضربة/مقذوف يصيب مرة واحدة لكل activation. المقذوف يستخدم swept AABB لمنع المرور عبر الخصم بين تحديثين. لا يُستعمل كامل حجم الصورة كصندوق ضرر.
- التفادي يمنح فترة قصيرة دون إصابة ويغير الموقع، والصد يقلل الضرر باحتمال وكلفة وcooldown. الرد الهجومي يرفع أولوية هجمة قريبة بعد الدفاع؛ ليس شجرة AI معقدة.
- فحص hurtboxes يمنع تداخل الجسمين في المباراة، والاندفاع والدفع والقفز مقيدة بالساحة.
- عند HP=0 تتوقف كل الإصابات والمقذوفات فورًا؛ يمر الخاسر برد فعل ودفع ثم KO، والفائز بوضعية نصر. بعد 90 تحديثًا، نحو 3.6 ثانية، يُزال الزوج وتُعاد HP والطاقة وتبدأ حركة Fall جديدة ثم السلوك الطبيعي. لا تُحذف الشخصية.
- الإيقاف اليدوي ينظف المباراة والمؤثرات فورًا. السحب أو Follow Cursor أو تغيير السلوك ينهي المباراة قبل تنفيذ السلوك العادي. فتح قائمة أحد المقاتلين أو إيقاف حركته يعلق الزوج مؤقتًا.
- لا يستدعي محرك القتال أي تحريك أو تدمير لنوافذ التطبيقات.

## المؤثرات والأداء

تم توليد مؤثرات أصلية هندسية صغيرة مناسبة لـChibi: slash، impact، dust، energy، projectile، spark، blue، red، fire، lightning. كلها PNG شفافة بأبعاد 96×96 وأربع إطارات. شكل المقذوف يختلف بين kunai وshuriken، وألوان الطاقة تختلف حسب الحزمة. تأثير clone يعرض صورة الشخصية بشفافية محدودة.

لا توجد مؤقتات جديدة للمباراة أو المؤثرات؛ يستخدم القتال تحديث Manager الحالي عند 25Hz. الصور تفك مرة عند بدء المباراة، ونوافذ VFX يعاد استخدامها، وتحديثات EDT تتجمع لتجنب تكدس الطابور. عدد المقذوفات محدود إلى 8، والمؤثرات إلى 48، وعمر المقذوف إلى 250 تحديثًا كحد أقصى. النافذة تنتهي عند إنهاء الزوج، وتُلغى آخر لقطة رسم وتُزال مراجع الصور.

تعاد مشاركة native bitmaps الخاصة بالشخصيات عبر ImagePairs. تصحيح Windows DPI يحفظ النسخ المحجمة ويحرر مقابض GDI بواسطة Cleaner عند زوال الصور، بدل إنشاء bitmap في كل إطار. لم يُنفذ قياس CPU طويل أو اختبار تحميل لعشرات الشخصيات؛ التحقق يغطي مباريات ثنائية وتشغيل خمس شخصيات معًا.

## التحقق النهائي

بيئة التنفيذ: Windows 11، JDK 25.0.3، وملفات Java مبنية بـ`--release 21`.

`mvn clean package` عبر Maven المرفق: **BUILD SUCCESS**. النتيجة `target/ShinobiMate.jar`. تحذيرات Maven تخص الموارد المتكررة في shaded JAR وJansi/Unsafe وبعض الأنواع غير المحددة في الكود السابق. Maven نفسه لا يحتوي على اختبارات JUnit في هذا المشروع؛ اختبارات القتال شُغلت منفصلة بعد البناء بواسطة السكربت.

الاختبارات الآلية:

- 144 مباراة ببذور ثابتة: Naruto/Sasuke، Gojo/Sukuna، Asta/Naruto، 48 مباراة لكل زوج؛ Scaling=0.75/1/1.5، شاشات ذات أصل سالب وموجب.
- الاقتراب والاتجاه وعدم تداخل الجسمين، hitboxes، startup قبل الضرر، إصابة واحدة لكل activation، cooldown، المقذوفات السريعة، dodge/block، الدفع، حدود الشاشة، KO والنصر وإعادة HP والتنظيف.
- اختبار نموذج وإدارة فعلي عبر Manager/Mascot: لا بدء تلقائي، اختيار خصم من القائمة العربية، تمييز النسخ المكررة، قفل الزوج، استمرار تحديث bystander، تعليق الطرفين، إيقاف من الطرف الثاني، rematch، السحب والإفلات، إعادة تحميل الحزمة، Follow Cursor، وإزالة أحد المقاتلين.
- 300,867 تحققًا آليًا خلال 72,814 تحديث قتال في تشغيل الاختبار النهائي.
- اختبار Main الحقيقي مع خمس حزم ونوافذ Windows: قائمة Right Click العربية، اختيار الزوج، VFX شفافة لا تلتقط الماوس ولا تأخذ التركيز، السحابة المثبتة تتبع المقاتلين، حدود نوافذ المقاتلين، عزل الآخرين، وإزالة نافذة VFX عند الإيقاف. جُرب الزوجان الإضافيان في العرض الأصلي أيضًا.
- فحص لقطة العرض كشف خلل DPI الأصلي؛ بعد إصلاحه ظهرت الشخصيات والمؤثرات على الشاشة. تغير عدد تحققات العرض حسب أحداث VFX العشوائية؛ سجل التشغيل النهائي موجود في `output/combat-desktop-check.log`.
- رفض إصدار profile غير مدعوم وDTD خارجي. رسالة Fatal Error في بداية سجل الاختبار ناتجة عن ملف اختبار مرفوض عمدًا، وليست فشل الاختبارات.

## ما يحتاج رسومات أو تحسينًا لاحقًا

- Sprites أصلية مخصصة لكل punch/kick/sword swing، رفع سيف أستا، شحن التقنيات، رد الفعل، KO الكوميدي ووضعيات نصر مختلفة. الوضعيات الحالية تؤدي الغرض للمحرك، لكنها لا تعرض كل حركة بالسيف أو اليد بالتفصيل.
- رسوم clone هجومية متعددة بدل استعمال صورة الوقوف الشفافة، وتعابير مختلفة للتفادي السريع والحاجز.
- مؤثرات chakra/cursed/anti-magic مرسومة يدويًا أو بأطلس متقن بدل الأشكال الهندسية الأولية الحالية.
- ضبط توازن القتال بعد مراجعة المستخدم، وقياس أداء وGDI/heap لمدة طويلة. لا توجد نتيجة تدّعي توازنًا تنافسيًا أو اختبار ذاكرة طويلًا.
- Team Battle 2v2 يبقى مرحلة لاحقة؛ البنية الحالية مباراة ثنائية فقط.

الحزم والمؤثرات والـJAR الناتج نُسخت إلى مجلد البرنامج المحمول. النسخ المشغلة سابقًا تحتاج إغلاقًا وإعادة فتح لكي تستخدم الإصدار الجديد؛ لم يُنه أي برنامج للمستخدم تلقائيًا.
